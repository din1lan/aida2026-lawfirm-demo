# 客戶進度回報草稿：規格

> 版本：範本版 v1（2026-11-04）｜分支 `feature/progress-report`
> 系統內全部是假資料。這個功能只「產生草稿」，**不會自動寄出、不會把資料送到任何地方**。

## 1. 使用情境

律師打開某一件案件的「案件詳情」→ 按「📨 產生進度回報」→ 跳出草稿視窗：

1. 系統依案件資料自動組出一則給當事人的訊息
2. 律師可以補兩個選填欄位（最近一次開庭結果、要請當事人準備的事），草稿會即時更新
3. 律師可以直接在草稿框裡改字
4. 按「複製」→ 自己貼到 LINE 或 Email 送出

## 2. 訊息結構（依序；資料缺的段落整段省略）

| # | 段落 | 例句 | 什麼時候出現 |
|---|------|------|------|
| 1 | 稱呼 | 林小華 您好： | 一定出現（沒有姓名就寫「您好：」） |
| 2 | 開場 | 以下向您報告「損害賠償」案件（案號 113訴101）目前的進度。 | 一定出現；案由、案號缺哪個就省略哪個 |
| 3 | 目前階段 | 【目前進度】本案目前在第一審法院審理中。 | 有訴訟階段時；調解中再加一句 |
| 4 | 上次開庭 | 【上次開庭】7 月 28 日已開庭。結果：法官請雙方補資料。 | 今天以前有開庭紀錄時；有填「開庭結果」才加「結果」那句 |
| 5 | 下次開庭 | 【下次開庭】2026 年 8 月 5 日（星期三）下午 2:00，地點：臺灣桃園地方法院民事庭 第三法庭。 | 今天以後有開庭時（只列最近一場） |
| 6 | 近期期限 | 【近期重要日期】・7 月 27 日前：補繳裁判費<br>・7 月 30 日：收到民事判決後的法定期限截止 | 今天起 30 天內的期限（最多 3 筆）。只列「動作期限」與「一般法定期限」；系統內部的「提前提醒」「筆錄調閱確認」不列 |
| 7 | 請您配合 | 【需要您協助準備】・醫療收據正本 | 有填「要請當事人準備的事」時（一行一項） |
| 8 | 結尾 | 如有疑問，歡迎與我們聯絡。 | **一定出現，固定這一句** |
| 9 | 署名 | 王大明律師 敬上 | 有承辦律師時 |

## 3. 用到哪些欄位

| 段落 | 來源（系統既有資料） |
|------|------|
| 稱呼 | 案件「當事人」`person` |
| 開場 | 案件「案由」`cause`、「案號」`caseNumber` |
| 目前階段 | 案件「訴訟階段」`status`（委任／起訴／一審／二審／三審／執行／已結案），「目前調解中」`mediationOngoing` |
| 上次／下次開庭 | 本案的開庭紀錄：日期 `date`、時間 `time`／整日 `allDay`、法院 `courtNameRaw`（沒有就用案件的 `court`）、法庭 `courtroom` |
| 近期期限 | 本案的期限：日期 `computedDeadline`、事項 `action`（沒有就用 `eventType`）。一般期限的 `eventType` 是觸發事件（例：收到民事判決），改寫成「收到民事判決後的法定期限截止」 |
| 開庭結果、請您配合 | **新增的兩個選填欄位**，在草稿視窗內填寫，存在案件上（`progressReportNotes.lastResult`、`progressReportNotes.clientTodo`） |
| 署名 | 案件「承辦律師」`attorneys` |

**刻意不用的資料**：身分證字號、電話、地址、收費與代墊款、對造資料、事務所內部任務、工時、AI 閱卷內容。這些不該出現在給當事人的訊息裡。

> 原本系統沒有「開庭結果」與「當事人要準備的事」欄位，所以由律師在草稿視窗補上；不從內部任務自動抓，避免把內部工作內容寄給當事人。

## 4. 缺資料怎麼處理

- 某一段的資料完全沒有 → **整段不寫**，不出現「未填」「無」「—」「undefined」等字
- 欄位只填「—」「-」「無」「未填」或空白 → 視為沒有資料
- 日期格式不對（不是 YYYY-MM-DD）→ 該筆不採用
- 時間沒填或整日 → 只寫日期，不寫時間
- 法院、法庭缺一個 → 只寫有的那個；兩個都沒有 → 不寫「地點」
- 文字很長 → 期限事項最多 40 字（超過以「…」截斷）；律師自己填的兩個欄位不截斷（律師自己寫的，由律師負責），但多餘空白會整理掉
- 跨年的日期才寫年份（例：下次開庭一律寫年份，上次開庭與期限同年就省略年份）

## 5. 不能出現什麼

1. **對案件結果的預測或保證**：範本本身不寫「一定」「保證」「勝訴」「有把握」「穩贏」「應該會贏」之類的話
2. 律師自己填的內容若含上述字眼，或含疑似身分證字號／手機號碼，草稿視窗會**顯示黃色提醒**（不自動刪，由律師決定）
3. 法律術語堆疊：階段一律用白話說明（例：「執行」→「進入強制執行程序，也就是請法院協助實際執行」）
4. 收費、代墊款、對造個資、內部任務
5. 系統字樣：`undefined`、`null`、`NaN`、「未填」

## 6. 不做的事（本版範圍外）

- 不自動寄出（沒有寄信、LINE 串接）
- 不用 AI、不需要 API 金鑰、不連網
- 「AI 潤稿」只預留接點：`ProgressReport.setPolisher(fn)`。之後若接上，`fn(草稿文字)` 回傳潤稿後文字，視窗才會出現「AI 潤稿」按鈕；本版沒有設定，所以看不到這顆按鈕

## 7. 技術接點（給工程人員）

- 程式：`modules/progress-report.js`（瀏覽器掛在 `window.ProgressReport`；Node 可 `require` 做測試）
- 核心是純函式 `buildProgressReport({ caseData, hearings, deadlines, notes, today })`，回傳文字
- `index.html` 只改兩處：載入這支 js、在案件詳情加按鈕並呼叫 `ProgressReport.open(...)`
- 測試：`node tests/progress-report.test.js`
