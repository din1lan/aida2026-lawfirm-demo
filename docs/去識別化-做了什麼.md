# 去識別化：做了什麼

> 分支：`feature/deidentify`（**沒有動 main**，沒有開 PR、沒有合併）｜日期：2026-11-04

## 一、做了什麼

1. **規格**：`docs/去識別化-規格.md`（要遮什麼、人名怎麼抓、代號格式、還原、預覽、限制）
2. **獨立模組** `modules/deidentify.js`（新檔案，原本的程式只加一行引入）
   - `deidentify(文字, 已知名單)` → 遮好的文字＋對照表
   - `reidentify(文字, 對照表)` → 換回真名（AI 改寫成「當事人 A」「[對造A]」「當事人Ａ」也認得）
   - `reidentifyDeep`（整包 AI 回傳一起還原）、`findLeftoverTokens`（抓 AI 自己編的代號）、`knownNamesFromCase`（從案件資料帶入名單）
   - 不碰任何儲存、不連網、不印 console；之後書狀初稿、LINE 接待、自動填案件資料可直接共用
3. **接到「AI 智慧閱卷」**（`index.html`）
   - 引擎選 Gemini 按「開始分析」→ 先跳出「🛡️ 將送出的版本」：左邊列出每一筆（可取消勾選、可手動補遮），右邊是 AI 實際會看到的全文，按「確認送出」才送；按「取消」什麼都不送
   - 角色指令裡原本寫著本所律師真名（「本事務所律師為：王大明律師…」），也一併換成代號
   - 結果頁標示「🛡️ 已去識別化 N 項後送出」；若 AI 回傳了無法還原的代號，會顯示 ⚠ 提醒
   - 新增引擎選項「去識別化測試（Gemini 假回應，不連網）」：用固定假回應走完整流程，不需要金鑰、不會連到 Google
   - 模組沒載入時直接中止送出（寧可不送，也不送未遮的原文）
4. **測試**：`tests/deidentify.test.js`（用 `node tests/deidentify.test.js` 執行）

## 四、還沒做的

1. **只接了 AI 閱卷**；書狀初稿、LINE 接待、AI 自動填案件資料還沒接（模組已可直接共用）
2. 會漏的情況（詳見規格第 2、7 節）：前面沒有「原告、被告、房東」等角色字的陌生人名；只寫名不寫姓、綽號、英文名；罕見姓氏；店名（例如示範文件的「小巷咖啡」就沒自動抓到，要手動補）；LINE ID、車牌；PDF 斷行切開的名字
3. 案件資料目前沒有「關係人」欄位；模組已支援 `relatedParties`，加欄位後就會自動帶入
4. 預覽畫面「手動補遮」的名字不會記住，下次分析要重加（刻意的：避免把名字存進瀏覽器）
5. 尚未用真實 Gemini 金鑰實測 AI 是否乖乖保留代號（依指示未呼叫）；還原已能處理常見改寫，認不出的會顯示 ⚠
6. 還沒用真實（已授權）卷宗抽測漏遮率
