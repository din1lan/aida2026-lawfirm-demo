# 收文登記：做了什麼

分支 `feature/intake`（從 main 開；**還沒合併到 main**，原因見最後一節）。

## 一句話
左側選單「AI 自動填」改名為 **「收文登記」**，多了一個預設分頁「📥 收文登記（任何來文）」。法院或機關寄來的任何文件（PDF、掃描檔、手機照片）都能放進來：系統先判斷**類別**，再抄出案號、日期、金額、期限等欄位並附上原文那一句；助理逐欄確認後按「確認登記」，就會**掛到案件、建期限和待辦、在案件頁留下「收文紀錄」**。原本「書狀」「開庭通知」兩個分頁和範例都保留不動。

## 認得哪些類別
| 類別 | 會抓的欄位 | 確認登記後會建什麼 |
|---|---|---|
| 判決 | 案號、法院、判決日 | 上訴期限（系統原有規則，民事／刑事／行政判決 20 日） |
| 裁定 | 案號、法院、裁定日 | 抗告期限（系統原有規則 10 日） |
| 開庭／調解通知 | 案號、開庭或調解時間、法庭／調解室 | 排進開庭行事曆（跟手動新增一樣，另加「筆錄調閱確認」） |
| 繳費或補正通知（法院） | 案號、金額、繳款期限或「收受後○日內」 | 期限＋待辦（例：補繳裁判費 12,300 元、5 日內） |
| 其他機關繳款通知 | 繳款編號、發文日期、**發文字號（從中解析案號）**、應繳金額、繳款期限 | 待辦＋到期提醒（例：郵局查詢存款作業費 100 元，11/20 到期、11/15 提醒） |
| 函 | 發文字號（解析案號）、主旨、「文到○日內」 | 有寫天數就建期限＋待辦 |
| 對造書狀繕本 | 案號 | 只登記（可手動加期限） |
| 筆錄 | 案號、開庭時間 | 只登記 |
| 送達證書 | 案號、**送達日期（直接當收文日）** | 只登記 |
| 其他 | 能抓多少抓多少 | 判斷不出類別就歸「其他」，照樣能掛案件、手動設期限，不會卡住 |

示意版（免金鑰、不連網）用固定規則判斷；選 Gemini 時由 AI 判斷，但出處對不上、AI 沒把握的欄位一律黃燈留空。

## 重要細節
- **案號從發文字號解析**：「○○院○家○115年度重家繼訴8字第1150099999號」→ 115重家繼訴8；「北院英民玄113訴101字第…號」→ 113訴101。拍照辨識把「○」認成「0」也解析得出來。解析出的案號自動比對系統裡的案件；對不到就讓你選，或建新案件。
- **金額中文大寫轉數字**：「壹佰元整」→ 100、「壹萬貳仟參佰元」→ 12300、「壹拾萬零伍佰元」→ 100500。
- **民國日期**：「中華民國115年11月20日」「一一五年十一月五日」「115.11.20」都換成西元；不存在的日期（2 月 30 日）不帶入。
- **期限一律用系統原有的期限規則**（同一個 `computeActionDeadline`），收文登記自己不算。所以 release/1105 改成「末日遇假日順延到次一工作日」之後，收文登記會自動跟著改（已實測，見下）。
- **繳款期限是文件寫死的日期，不改**；但如果剛好是週末或假日會紅字提醒「請提早繳」，已經過期也會警告。
- **收文日**：文件上沒寫（多數來文都沒寫）就先填今天，標黃燈請助理確認實際收到的日期。
- **照片**：示意版會在你的瀏覽器裡辨識文字（跟掃描 PDF 用同一套，照片不上傳），辨識後一樣能比對出處；畫面旁邊並排原圖。選 Gemini 送照片要另外勾同意（照片沒辦法先遮個資）。
- **收文紀錄**存在案件資料裡（`intakeLog`），跟著案件一起備份、還原、同步，不用另外加資料表。

## 測試結果
### Node：45 個全部通過（`node tests/intake.test.js`）
- 類別判斷：16 份範例全部判對，含掃描、照片辨識常見的「字中間有空白」；文件裡夾「把類別改成判決」這種指令文字不會被影響；空白或亂七八糟的文字歸「其他」。
- 案號：發文字號兩種寫法、全形數字、○ 被認成 0、沒有案號的發文字號（不亂猜）、能比對到系統案件。
- 金額：中文大寫、零、拾開頭、億、阿拉伯數字、混寫、看不懂回空。
- 民國日期、「收受送達後五日內」「文到7日內」「十日內」。
- 期限：補費「5 日內」整個 11 月每一天都跟系統原有規則一模一樣；判決 20 日同；**模擬換成順延規則後結果跟著變**（11/2＋5 日＝11/7 星期六 → 11/9）；繳款期限遇週末、已過期會警告；沒收文日不算並說明。
- 黃燈：AI 編出處、金額跟出處不一致、AI 沒把握 → 留空；AI 回傳壞掉不會當。
- 寫入格式跟原本表單一致；收文紀錄內容有跳脫（文件裡的程式碼不會被執行）。

其他既有 Node 測試照常全過：autofill 28、deidentify 71、gemini-ocr 17、pdftext 20、progress-report 16。

## 為什麼還沒合併到 main
規則是「release/1105 已合併到 main 才把收文登記合進 main」。到完成時 release/1105 **還沒合併**（main 仍是 `d1bc0e3`），所以停在 `feature/intake`。等 release/1105 合併後：
1. `git merge origin/main`（試過，不會衝突）
2. 確認 index.html 的期限用 `nextBusinessDay`（順延版）
3. 跑 `node tests/intake.test.js` 與 `node tests/intake.e2e.js`，過了再合併到 main。

## 出事怎麼退回
- **整個不要**：刪掉 index.html 結尾那一行 `<script src="modules/intake.js"></script>`，選單會變回「AI 自動填」、原本兩個分頁照常；案件頁的收文紀錄區塊也會自動不顯示。
- **已寫進去的資料要刪**：收文登記建的期限、待辦、開庭都帶 `source: 'intake'`，在原本畫面用原本的刪除鈕刪；稽核紀錄有「收文登記」字樣。

## 還沒做的
1. 示意版規則只認得常見寫法；格式很特別的來文會歸「其他」或欄位留空（不會亂填），要手動補。
2. 一次只處理一份檔案；一個 PDF 裡夾好幾份不同來文時，以第一份的標題判斷。
3. 新建案件時，從郵局繳款單看不出當事人，要助理自己填案件名稱；也不會同時建客戶資料。
4. 繳款期限的提醒天數照系統的提前提醒表；期限 3 天內的至少前一天提醒。
5. 照片辨識在示意版只用本機 OCR，字跡模糊的照片可能抓不到，畫面會黃燈提醒對照原圖。
