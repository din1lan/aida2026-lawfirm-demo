# PDF 轉錄修正（分支 `fix/pdf-cjk`，2026-11-04）

## 一句話結論
網站讀 PDF 時沒有告訴 pdf.js「中文字型對照表」放在哪裡。遇到台灣法院常見、**沒有內嵌**的中文字型（細明體、標楷體這類），pdf.js 不知道每個字碼對應哪個中文字，**整份中文全部被丟掉**，還被誤判成「掃描檔」。補上對照表位置後，測試文件 100% 讀到。

## 原因（白話）
- PDF 裡的中文常常不是直接存「字」，而是存「字碼」，要查一張對照表（CMap）才知道是哪個字。
- 字型有內嵌、又附對照表的 PDF（例如 Word、瀏覽器列印出來的）→ 原本就讀得到。
- 字型沒內嵌、靠標準對照表的 PDF（法院、公文系統常見）→ pdf.js 要去下載標準對照表；原本沒給下載位置，pdf.js 直接放棄這個字型，該字型的字全部消失。
- 瀏覽器主控台會出現：`The CMap "baseUrl" parameter must be specified`。

其他懷疑點也查過：
| 懷疑點 | 結果 |
|---|---|
| 片段串接（`str + hasEOL`）吃字或亂序 | 不會吃字。但有些 PDF 換行時不帶換行記號，前後兩行會黏在一起 → 新寫法看到「位置往下移」就補換行（原有 7 份示範 PDF 輸出逐字不變） |
| 頁數或字數上限截斷 | 兩處讀取都沒有上限；25 頁、一萬多字完整讀到 |
| AI 閱卷送 Gemini 前截斷 | 沒有截斷（整份逐頁組好直接送） |
| 掃描頁／圖片頁 | 原本默默跳過，使用者不知道少了哪頁 → 現在畫面紅字寫「第 N 頁是圖片、讀不到文字」 |

e2e 的跑法：專案根目錄 `python3 -m http.server 8765`，再 `node tests/xxx.e2e.js`。
**測試環境限制**：這台雲端機器連不到外部 CDN，所以測試時把 pdf.js 3.11.174（含 `cmaps/`、`standard_fonts/`）與 xlsx 0.18.5 換成 npm 上**同版本**檔案（設 `CDN_DIR`），Tailwind 用 3.4.17 先編好的樣式頂替。只在測試瀏覽器裡替換，**沒有放進專案、網頁的引用也沒改**。正式網路上會直接從 cdnjs 抓對照表；建議合併前用一般網路開一次、上傳 `tests/fixtures/pdf-cjk/T1_CID字型_3頁.pdf` 確認。沒有呼叫真的 Gemini、沒用任何金鑰。

## 要注意的地方
- 讀這類字型時，瀏覽器會多從 cdnjs 下載一兩個小檔（對照表，各幾 KB～幾十 KB）。沒網路時 pdf.js 本來就載不進來，情況跟以前一樣。
- 「圖片頁」判斷：一頁少於 5 個字而且有畫圖片才算。完全空白的頁不會提示。

## 出事怎麼退回
- 還沒合併：不合併 `fix/pdf-cjk` 就好，main 完全沒動。
- 已合併後要退：在 main 上 `git revert <這次的合併 commit>` 再推上去，網站就回到修改前。
- 只想暫時關掉新讀法：把 `index.html` 第 10 行 `<script src="modules/pdftext.js"></script>` 刪掉**不行**（兩個功能會找不到讀取函式）；請用上面的 revert。

## 建議（這次沒做）
- **OCR（文字辨識）**：掃描頁目前只提示、讀不到。可考慮瀏覽器端的 Tesseract.js（繁中模型約 10MB 以上、一頁要數秒），或把該頁圖片交給 Gemini 讀（要另外處理個資遮蔽：圖片沒辦法先遮）。
